核心观点是：两页图说明，单纯靠硬件拉近距离或加带宽，都不足以支撑每步同步的层次化 DP。下一步的重点是把层次化集合通信和低频或重叠通信结合起来，再按方案确定 WAN 的目标。 以下是我基于这两页的推论，数字都依赖模型假设。

对未来硬件需求的观点

1. 硬件目标可按带宽档位划分

┌──────────────────────┬───────────────────────────────────────────────────┐
│ 档位（每链路、单向） │                   能支撑的方案                    │
├──────────────────────┼───────────────────────────────────────────────────┤
│ 100 Pbps 以上        │ 层次化 DP（100 km 需 139 Pbps），不宜作为现实目标 │
├──────────────────────┼───────────────────────────────────────────────────┤
│ 约 3–4 Pbps          │ PP 不去重、DiLoCo H=30                            │
├──────────────────────┼───────────────────────────────────────────────────┤
│ 约 0.3–0.6 Pbps      │ PP 去重、Streaming                                │
├──────────────────────┼───────────────────────────────────────────────────┤
│ 约 0.01–0.05 Pbps    │ Decoupled、Eager                                  │
└──────────────────────┴───────────────────────────────────────────────────┘

2. 近距离不能代替带宽
从 1000 km 缩到 100 km，层次化 DP 只是从无解变成 139 Pbps；DiLoCo H=30 只降 10%，后三种几乎不变。空芯光纤也一样：100 km 时层次化 DP 只从 139 降到约 121 Pbps。所以站距并不是这些方案的主要杠杆。

3. 距离影响的是 PP 和小预算方案
PP 从 100 km 到 1000 km 的带宽需求约涨 36%，后三种几乎不变。因此 DiLoCo 系列的选址可以更宽松，这对分散利用电力有利；PP 跨站则更依赖站距和调度。

4. 瓶颈在 WAN 出口，不在单卡 NIC
美国 8 站时 NIC 总速率约 93 Pbps，WAN 只有 3 Pbps。跨站通信更需要 DCI（数据中心互联）的容量、限速和长距离缓存能力，而不是单卡 NIC 更快。不过站内 DP 依然受 NIC 和 scale-up 域限制（第 11 页），这是另一条硬件主线。

对层次化集合通信的观点

1. 层次化是必要条件，不是解决方案
它把不感知拓扑时的约 57 Pbit 跨站流量降到约 1.15 Pbit，约 50 倍。但是做完之后，100 km 下仍要 139 Pbps。

2. 更大的杠杆在于不阻塞和降频
这些都是在层次化基础上进一步改进（100 km、8 站）：

┌────────────────────────────────┬─────────────┬───────────────┐
│              组合              │  所需带宽   │ 相对 139 Pbps │
├────────────────────────────────┼─────────────┼───────────────┤
│ 层次化 DP，5% 预算             │ 139 Pbps    │ 基准          │
├────────────────────────────────┼─────────────┼───────────────┤
│ 空芯光纤（时延降到 2.75 ms）   │ 约 121 Pbps │ 降 13%        │
├────────────────────────────────┼─────────────┼───────────────┤
│ 通信与计算完全重叠（β=100%）   │ 约 4.8 Pbps │ 降约 29 倍    │
├────────────────────────────────┼─────────────┼───────────────┤
│ 每 30 步同步一次（H=30，β=5%） │ 3.16 Pbps   │ 降约 44 倍    │
├────────────────────────────────┼─────────────┼───────────────┤
│ H=100 且 4 bit（β=5%）         │ 0.235 Pbps  │ 降约 590 倍   │
└────────────────────────────────┴─────────────┴───────────────┘

所以集合通信的研究重点，应从缩短单次通信转向非阻塞、可重叠、可分片。

3. DiLoCo 也依赖层次化结构
站内仍然每步同步，只是跨站变成低频。所以层次化集合通信是这些方案共同的基础，不会被 DiLoCo 取代，只是跨站这一层的流量模式变了。

4. 跨站这一层必须感知拓扑并限速
- 按切片分散： 对应 die 之间按切片传输，让单条链路的流量约等于一个模型大小，不随站点数增加。
- 限速： NIC 总速率是 WAN 的约 31 倍，不限速就会拥塞丢包。
- 长距离传输： 3 Pbps 下，往返窗口内的在途数据量在 100 km 时约 375 GB，1000 km 时约 3.75 TB，这对 RoCE 的拥塞控制和缓存设计压力很大。平摊到每个 die，100 km 时约 3 MB，单流压力并不大，难点在总量和突发。

5. 集合通信软件的优化不比硬件差
TP 组内去重能把 PP 从 3.58 降到 0.448 Pbps（8 倍），比从 1000 km 缩到 100 km 的效果（36%）大得多，而且不用改硬件。

引用时的注意事项

- 带宽结论依赖假设： 5% 预算、step 0.246 s、8 站都会明显影响结论。如果 step 是 0.864 s，DiLoCo H=30 也会变得轻松很多。
- 没有证明训练质量： DiLoCo 的降频代价和 72T 下的收敛都未验证，所以“降约 590 倍”只代表带宽，不代表方案更好。
- PP 是估算： 尤其是 1000 km 的 0.448 和 3.58 Pbps，假设了等待全部无法掩盖。
- 在途数据量是我的粗算： 真实的 RoCE 表现要靠仿真或实测，这也是你负责的 100 km 有损方向可以补充的部分。
